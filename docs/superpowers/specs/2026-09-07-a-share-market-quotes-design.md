# 大 A 行情页设计（方案 A：请求时直拉 AKShare）

日期：2026-09-07  
状态：已确认方案 A，实现进行中  
范围：规划与接口约定，本文不含实现代码

## 1. 目标

在 Maddox Quant 增加「行情」页面，展示沪深京 A 股指数、市场涨跌概况、行业板块与个股报价。数据源为 AKShare（东方财富等网页接口封装）。

**方案 A**：用户打开页面或切换筛选时，后端当场调用 AKShare，聚合后返回前端。不新增行情快照表，不增加 APScheduler 采集任务，不引入 Redis。

## 2. 方案 A 的可行落地（必须带进程内短缓存）

纯「每次请求都打东财」在工程上不可用：

- `stock_zh_a_spot_em()` 全市场约数十秒，偶发只返回部分行
- 同一用户刷新、多标签、列表翻页会把源站打爆
- 源站限流或改版时，页面直接空白

因此方案 A 的可行形态是：

**请求路径触发 AKShare + 后端进程内 TTL 缓存（内存，不落库）。**

这仍是 A，不是 B：

| | 方案 A（本设计） | 方案 B（已放弃） |
|--|--|--|
| 谁触发拉数 | 用户请求 | 定时任务 |
| 数据放哪 | 进程内存，TTL 过期 | PostgreSQL 快照表 |
| 无用户访问时 | 不拉数 | 仍按 cron 拉 |
| 重启后端 | 缓存清空，下一次请求重拉 | 库里仍有上一份 |

TTL 建议：

- 指数 / 板块 / 全市场快照：60–120 秒
- 个股日 K（二期）：5–15 分钟
- 缓存键按「接口名 + 参数」区分

进程内缓存用简单 dict + 过期时间即可，与现有「仅 PostgreSQL 持久化」不冲突。Docker 单副本 backend 下足够；多副本时各进程各自缓存，可接受。

## 3. 产品范围

### 一期（本设计覆盖）

1. 导航「行情」→ `/market`
2. 指数条：上证综指、深证成指、创业板指、沪深 300
3. 市场概况：上涨 / 下跌 / 平盘家数，涨停 / 跌停，两市成交额（由个股快照聚合）
4. 行业板块涨跌榜（东财行业板块）
5. 个股列表：代码、名称、最新价、涨跌幅、涨跌额、成交额、换手、市盈率；搜索、排序、分页
6. 页面展示 `as_of`（本次缓存生成时间）与加载/失败态
7. 个股代码可跳转研报搜索 ` /reports?q=代码`，可一键关注（复用现有 watchlist）

### 二期（明确后置）

- `/market/stocks/[code]` 报价 + 日 K
- 自选股行情条
- 概念板块、资金流、分时、五档盘口

### 不做

- 逐笔 / Level-2
- 港股美股
- 把 AKShare 结果写入 Postgres
- 无用户访问时的后台轮询

## 4. 页面与交互

```
/market    唯一一期路由
```

布局（与现有研报页同一套 zinc 风格，涨跌红绿：红涨绿跌）：

1. 指数卡 × 4，失败时单卡显示「暂无」
2. 市场温度：涨跌家数、涨停跌停、成交额；旁注「数据来自公开网页，约延迟 1–2 分钟」
3. 行业板块 Top / Bottom 10
4. 个股表：默认按涨跌幅降序；`q` 搜代码或名称；每页 50 条

加载策略：

- 进入页面立即请求 `overview` 与 `boards`（相对轻）
- `stocks` 可能首次很慢：表格区用骨架屏，超时文案「行情源响应较慢，请稍后重试」
- 翻页 / 排序 / 搜索只打我们自己的 API，由缓存命中，不应再等数十秒
- 可选：每 60 秒静默刷新 overview；stocks 不自动全量刷新，避免叠请求

## 5. AKShare 接口约定

后端封装 `MarketProvider`，路由禁止直接 `import akshare`。

| 能力 | 接口 | 说明 |
|------|------|------|
| 指数 | `stock_zh_index_spot_em(symbol="沪深重要指数")` | 过滤 000001、399001、399006、000300 |
| 个股全表 | `stock_zh_a_spot_em()` | 主路径；超时或行数异常则拆 `stock_sh_a_spot_em` + `stock_sz_a_spot_em` + `stock_bj_a_spot_em` |
| 行业板块 | `stock_board_industry_name_em()` | 用于板块榜 |
| 交易时段判断 | 本地日历（工作日 9:15–15:10，不含法定假日可先简化） | 用于文案，不阻止拉数 |

字段统一为英文内部模型后再给前端，避免把「涨跌幅」等中文列名散落到 API。

股票代码统一 **6 位数字**，与 `watchlists.target_code`、`reference_items` 一致。

## 6. 后端 API（全部同步请求路径，读缓存或拉源）

```
GET /api/market/overview
GET /api/market/stocks?q=&sort=change_pct&order=desc&page=1&page_size=50
GET /api/market/boards?type=industry
```

行为：

1. 查进程内缓存，未过期则直接返回
2. 过期则调用 AKShare（单飞：同一缓存键并发只打一次源站）
3. 成功写入缓存并返回
4. 失败：若有过期缓存则降级返回并带 `stale=true`；否则 502，body 为统一错误结构

`overview` 可复用同一份个股全表缓存做涨跌家数聚合，避免指数和列表各拉一次全市场。

超时：单次 AKShare 建议 60–90 秒上限；API 对前端的 HTTP 超时要更长或由前端接受长时间 pending。Docker / uvicorn 保持默认即可，前端 fetch 超时建议 ≥ 90 秒（仅首次）。

不鉴权，与现有公开 API 一致。

## 10. 风险

| 风险 | 处理 |
|------|------|
| 首次打开很慢 | 骨架屏 + 文案；TTL 让后续交互快 |
| 全市场接口被截断 | 校验行数；拆沪/深/北兜底 |
| 源站失败 | stale 缓存；否则明确错误，不假装有数据 |
| 多用户同时冷启动 | 单飞锁，只打一次 AKShare |
| 数据版权 | 仅内网投研展示，非交易所授权行情 |

## 11. 一期验收

- `/market` 可打开，指数、板块、个股表有数据或有明确失败提示
- 同一进程内 2 分钟内第二次打开明显快于第一次（缓存命中）
- 搜索 / 排序 / 翻页不重复触发全市场拉取
- 不新增数据库表，Alembic 无行情相关迁移
- 现有研报 / 分析 / 关注回归不受影响
